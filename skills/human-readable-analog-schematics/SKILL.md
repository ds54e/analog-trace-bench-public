# Human-readable analog schematics

Make the circuit's operating structure recognizable before the reader traces individual nets. Treat electrical fidelity and visual readability as separate acceptance gates. Zero overlap or zero electrical diagnostics does not establish readability.

Read [the drawing rules](references/drawing-rules.md) before placement. For placement, wiring, or complaints about bends/detours, also read [the routing refinement](references/routing-refinement.md): endpoint alignment, shared trunks and the mandatory simplification pass. Read [the gallery evidence](references/gallery-evidence.md) when choosing a visual reference. For Analog Canvas or netlist conversion, also read [the verification workflow](references/analog-canvas-workflow.md).

## Workflow

1. **Freeze the electrical contract.** Record source/version, cell interface order, device identifiers, ordered pins including body, models, values, expressions, W/L, nf and m. Separate DUT from testbench and external loads. Preserve uncertain constructs; do not invent circuit functions or modify them for symmetry.
2. **Read the circuit before placing it.** Identify differential pairs, mirrors, cascode stacks, gain/output stages, bias sources, compensation, sensing and feedback. Use connectivity as evidence; mark uncertain interpretations. Write a short reading order and a list of relationships that must remain visibly connected. For an LDO, this normally includes output → divider/sense → error amplifier → gate driver → pass device; identify additional bias loops separately.
3. **Choose a visual grammar.** Use local left/right symmetry for matched branches, vertical device stacks for current paths, and a clear stage progression where it fits. Choose suitable examples from the evidence. Copy their relationships and information hierarchy, not their topology, sizes, omissions, or accidental flaws.
4. **Place for the connections as well as the motifs.** Set local matched-branch columns, device rows and common-source junctions. Align an interstage receiving gate with a suitable sending-node tap; reserve a straight trunk for shared gates. Choose symbol orientation from pin exit directions before routing. Align rows within a functional motif, not every PMOS/NMOS across unrelated stages. Keep related devices close and budget full label widths. Do not freeze an initial placement that forces needless doglegs.
5. **Route the relationships that explain operation.** Draw short mirror gate/diode ties, the local differential pair, forward signal path and compensation visibly. Prefer an explicit main feedback return. Use equal-net labels for distributed supplies/bias and genuinely remote blocks; never let them conceal the very relationship being explained. Routes should be orthogonal by default, with clear junction dots and unambiguous crossings. For this user, separate four-way connected junctions into two minimally offset T-junctions; reserve crosses for nonconnections. Preserve functional axes such as a vertical resistor divider; offset its taps rather than moving its resistors apart. Never join different nets to implement this preference. Read the exceptions in the rules.
6. **Set a deliberate information hierarchy.** Keep identifiers and decisive port/net names next to their objects. Default to the user's tight label profile in drawing-rules section 6: MOS names beside the body, passive name/value as a close aligned pair, port names at ports, internal names just above their wire. Use visual `M` for mega (e.g. `3M`, never `3meg` on the overview); preserve safe SPICE `meg` parameters. See the native formatter limitation in the verification workflow. Keep all original MOS sizes/multipliers in the editable project and an accompanying detail view or table; show them on the schematic if required or still legible. Never silently collapse m/nf into width. Explain hidden body ties explicitly and draw nonstandard body connections.
7. **Simplify routes and empty space, then review the renders.** Perform the routing-refinement pass before declaring the drawing readable. Challenge each interstage dogleg, repeated gate stub and unnecessary reversal: try moving a tap, junction, label or receiving device; do not merely shorten the existing detour. Keep a bend only for a concrete pin-direction, obstacle, separation or functional-reading reason. Preserve D–G ties and useful feedback shape. For LDOs, explicitly challenge every long horizontal gap; do not reserve label padding where no label exists. Auxiliary bias routes should not appear to enter an unrelated diode tie. Label the actual bias node and relocate the resistor/return when needed. At fit view check motifs/paths; at reading size check crossings, labels and values. Zero diagnostics or a favorable self-rating does not establish that unnecessary bends or whitespace are gone.
8. **Verify the electrical contract again.** Export from the final saved/reopened project and compare ordered pins, models, values/expressions, multiplicities and external port order to the source. A schematic-like SVG or lenient graph grade is insufficient. Report exact checks, unsupported syntax, and whether actual electrical simulation was run.

## Deliver

- Inspectable SVG and editable native project when the task requests a drawing; keep original and generated netlists and comparison results with them.
- A short explanation of the dominant signal/current/feedback paths and any label-based discontinuities.
- A candid visual assessment using the rubric. Do not claim that the gallery proves simulation validity or that an `ai=0` flag verifies individual authorship.
- For a rules-only request, provide the applicable rules and evidence; do not automatically rewrite the user's existing circuits.

When using headless or MCP drawing, apply the same rules as manual drafting. Automatic placement is a starting point. Correctness checks and visual review are both required before calling the result clean/readable.
